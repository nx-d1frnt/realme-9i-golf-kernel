# GolfCore v0.2.0-rc1 Balanced

Кандидат на базе проверенной версии v0.1.0-abi-v2 для Realme 9i 4G / RMX3491,
crDroid GSI Android 14 и существующей DFE-базы.

## Изменения

### ION: обнуление объектов без пустого конструктора

`boost_ion_info_cachep` создавался с пустым `init_once`, но объекты выделялись
через `kmem_cache_zalloc`. SLUB предупреждает о сочетании constructor и
`__GFP_ZERO`: обнуление может уничтожить результат конструктора.

Конструктор здесь ничего не делал. Он удалён, в `kmem_cache_create` передан
`NULL`, оба вызова zalloc сохранены. Размер и поля page_info не изменены.
Сам WARN в SLUB сохранён для остальных пользователей.

### Zram: корректная граница условия WARN

Проверка `___GFP_HIGH_ATOMIC_ZRAM` находилась после `WARN_ON_ONCE`, поэтому
предупреждение срабатывало даже для намеренно исключённых Oplus-выделений.
Исключение перенесено внутрь проверяемого условия. Для обычных недопустимых
сочетаний ATOMIC + DIRECT_RECLAIM предупреждение и снятие ATOMIC сохранены.
Для zram-маркера флаги остаются прежними. Это исправление диагностики,
а не изменение политики reclaim или подтверждённое ускорение.

### Touch: владение IRQ при LCD-before-touch resume

Вызов `tp_resume()` освобождает IRQ, а повторная регистрация выполняется
асинхронно в `speedup_resume`. Callback дисплея вызывал `enable_irq()` сразу
после `tp_resume()`, когда IRQ уже освобождён. Это соответствует стеку
предупреждения `irq_startup` из журнала базовой версии.

Теперь tp_resume сообщает, был ли IRQ освобождён. В этом случае callback
оставляет регистрацию рабочему потоку. Если resume пропущен, потому что
панель уже активна или обновляется её прошивка, callback по-прежнему
балансирует ранний disable_irq_nosync вызовом enable_irq. Режим
irq_trigger_hdl_support и порядок TP-before-LCD сохранены.

## Проверки до установки

Полная сборка и упаковка boot завершены. Все 2087 импортов 33 модулей
прошли проверку CRC; повторная распаковка подтвердила сохранение ramdisk,
DTB, header, fstab и DFE. Версия и SHA-256 артефактов записаны в
[GOLFCORE_V0.2_BUILD.json](GOLFCORE_V0.2_BUILD.json).

`tests/check_regressions.py` компилирует фактические функции tp_resume и
fb_notifier_callback из исходника с моделью владения IRQ. Проверены 32
сочетания порядка resume, состояния suspend, загрузки firmware, режима
irq_trigger_hdl_support и int_mode. Включение освобождённого IRQ считается
ошибкой; исходная версия воспроизводит эту ошибку, исправленная проходит.

Проверка флагов использует фактический блок из page_alloc.c: восемь сочетаний
ATOMIC / DIRECT_RECLAIM / HIGH_ATOMIC_ZRAM с VENDOR_EDIT и восемь без него.
Исходный vendor-вариант не проходит контроль предупреждения для zram-маркера.

```bash
python3 tests/check_regressions.py
```

Эти проверки подтверждают управляющую логику на хосте. Они не проверяют
конкурентность ядра, контроллер тачскрина или восстановление железа после сна.
Полная сборка отдельно проверяет все 2087 импортов 33 vendor-модулей.
Упаковщик проверяет сохранение ramdisk, DTB, header, fstab и DFE.

## Что сохранено

- Версия 4.19.157-perf+, vermagic, MODVERSIONS и публичный штатный сертификат.
- Включённые параметры штатного конфига, DTB и существующий DFE ramdisk.
- Частоты, schedutil, boost, размеры пулов ION и настройки thermal.
- LZ4 и размер zram 4 GiB, которые уже использует установленная система.

Название сборки находится в compile user/host, без изменения kernel release,
к которому привязаны штатные модули. Прирост автономности и производительности
не заявляется до сравнительных измерений.

## Проверка на телефоне

Статус кандидата: **ещё не установлен и не проверен на устройстве**.
Базовая версия и проверенные резервные boot/vendor сохранены локально.

Для сравнения можно снимать статистику на обеих версиях:

```bash
python3 tools/capture_state.py --output /path/to/local-baseline.json
```

Инструмент использует уже разрешённый root ADB Shell и только читает данные.
Он не переключает экран, не перезагружает телефон и не меняет настройки.
Снимки содержат локальную диагностику и не предназначены для коммита.
Для замеров расхода батареи нужны сопоставимые условия без USB-зарядки.

После установки нужны: загрузка Android и модулей, проверка экрана/сенсора,
камеры, звука, Wi-Fi и отпечатка; затем многократное включение экрана, сон
и повторное чтение журнала. Device-links WARNING пока не исправлен.
