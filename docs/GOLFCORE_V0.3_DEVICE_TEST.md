# GolfCore v0.3.0-rc1 — устройство, 14 ноября 2026

Realme 9i 4G / RMX3491, crDroid GSI Android 14, существующая DFE-база.
Код ядра: commit `d23b52cef30c6bdec22307ad31f60546423c2d90`.
Дополненные host-тесты: `b9eeb7a2395fba248a3da50ee4f0511a31ade57e`.

## Установка

Перед записью текущий boot сверён с проверенной копией v0.2 для отката.
После разрешения пользователя fastboot записал только boot; Android
завершил загрузку. Реальный `uname -r`: **4.19.157-GolfCore-v0.3**.

Хеш boot после чтения с телефона совпал с кандидатом:
`22e6091c55f60e1a650a56b5c055870574b2a9a23c7aa9a3ddce7d67096bed14`.
Vendor сохранил прежний SHA-256:
`cd8e27d652e70cec886f40980b7cfe0f1926635124ff183c6a8521ae03b16b95`.
Резервные образы остались локально.

## Первичные проверки

- Все 31 модуль, загружавшиеся на v0.2, загрузились; отсутствующих нет.
- Root доступен. Userdata — F2FS rw, crypto state остаётся unsupported.
- Zram активен с LZ4 и размером 4 GiB.
- Camera HAL видит две камеры; fingerprint HAL deaths=0.
- Три автоматических цикла экрана прошли: Dozing → Awake.
- Пользователь проверил сенсор, пробуждение, Wi-Fi, звук/микрофон,
  камеру и отпечаток. Ответ: «Всё работает, GolfCore виден».
- GolfCore Profiles v0.1.1 запустился после реальной перезагрузки,
  создал baseline для текущего boot_id и применил CPU Balanced / память
  balanced с включённым автозапуском. Сами идентификаторы загрузки в Git не включены.
- Значения памяти после автозапуска: swappiness=160,
  direct_swappiness=40, watermark_scale_factor=30.

В снятых журналах нет обнаруженных kernel panic, Oops, BUG, ошибок
версий/подписей модулей, сжатия или распаковки LZ4 и EROFS.
Сохраняются прежние предупреждения gpio_to_desc → pn544_probe (NFC)
и device_links_driver_bound. NFC отдельно не проверялся.

## Наблюдение zram, которое требует дальнейшего сравнения

В первом снимке при uptime около 82 секунд: failed_reads=0,
failed_writes=50, invalid_io=0. В предыдущей v0.2 отказы записи также
встречались, но в раннем снимке их было меньше. Нагрузки и условия загрузки
не были одинаковыми, поэтому причинность обновления LZ4 не установлена.

В дополнительных чтениях на uptime 306.88, 322.44 и 338.28 секунды
failed_writes оставался равен 50, failed_reads — 0. Сообщений
Compression failed / Decompression failed и ошибок I/O zram в снятых
журналах не найдено. OOM-kill в первом снимке: 0.

По исходникам zram счётчик учитывает отрицательные возвраты zram_bvec_rw,
включая неудачные попытки rw_page, после которых верхний слой может
повторно отправить bio. Нельзя считать все 50 значений доказанными
окончательными ошибками записи; точный путь этих отказов не трассировался.
Это наблюдение сохранено, а не объявлено исправленным или безвредным.

Сборка остаётся экспериментальной. Длительный сон, длительная стабильность,
расход батареи, скорость и коэффициент сжатия в сравнении с v0.2 ещё
не измерены. Необработанные журналы и личные снимки устройства в Git не добавлены.
