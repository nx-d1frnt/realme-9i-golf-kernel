# GolfCore Profiles v0.1.1

Модуль Magisk для **Realme 9i 4G / RMX3491 с GolfCore 4.19.157-perf+ или 4.19.157-GolfCore-v0.3**.
Проверен на crDroid GSI Android 14, Magisk 30.7.
Меняет шесть разрешённых sysfs/sysctl-параметров без пересборки ядра.
Текущая версия — экспериментальные профили, а не подтверждённое ускорение
или увеличение времени работы.

## CPU-профили

| CPU | Input boost | Задержка повышения частоты schedutil |
| --- | --- | --- |
| Balanced | Значение из исходного снимка, сейчас 80 мс | Исходное значение, сейчас 0 мкс |
| Battery | 40 мс | 2000 мкс для обоих кластеров |
| Gaming | 120 мс | Исходное значение, сейчас 0 мкс |

Значения input boost frequency остаются штатными. Gaming продлевает реакцию
на ввод, но не удерживает CPU/GPU на максимуме и не обещает прирост FPS.
Battery сокращает boost и ограничивает частоту пересчёта вверх; влияние
на автономность требует измерений. Максимальные/минимальные частоты,
настройки thermal и Power HAL не меняются.

## Память

| Режим | direct_swappiness | watermark_scale_factor | swappiness |
| --- | --- | --- | --- |
| stock | Исходное, сейчас 60 | Исходное, сейчас 25 | Исходное, сейчас 160 |
| balanced | 40 | 30 | Исходное, сейчас 160 |

В этой версии Oplus get_scan_count использует direct_swappiness для reclaim
вне kswapd, а vm_swappiness — для фонового reclaim. Снижение первого параметра
уменьшает относительный вес anon/swap-сканирования в прямом reclaim.
Небольшое увеличение watermark_scale_factor увеличивает расстояние между
порогами kswapd. Рабочая гипотеза — меньше сжатия на пути выделения памяти
приложению при более раннем фоновом reclaim. Это не гарантия уменьшения
задержек: при реальной нагрузке возможны и отрицательные эффекты.

Сохраняются LZ4, zram 4 GiB, page-cluster=0, правила LMKD и cgroup.
Swap не отключается и не пересоздаётся. Модуль не сбрасывает кэши, не
завершает приложения, не меняет FBE, разделы boot/vendor или SELinux policy.

## Использование

Установка ZIP — через Magisk, «Модули → Установить из хранилища».
Установка в recovery не поддерживается. В штатном ZIP по умолчанию выбран
CPU Balanced + память balanced с автозапуском после загрузки Android.
На тестовом телефоне модуль уже установлен и проверен без перезагрузки.

Кнопка **«Действие / Action»** в Magisk переключает только CPU:
Balanced → Battery → Gaming → Balanced. Выбранный режим памяти сохраняется.
Команды через ADB:

```bash
# Состояние, исходные и текущие значения
adb shell "su -c 'sh /data/adb/modules/golfcore_profiles/profile.sh status'"

# CPU-профили; текущий режим памяти сохраняется
adb shell "su -c 'sh /data/adb/modules/golfcore_profiles/profile.sh apply battery'"
adb shell "su -c 'sh /data/adb/modules/golfcore_profiles/profile.sh apply gaming'"
adb shell "su -c 'sh /data/adb/modules/golfcore_profiles/profile.sh apply balanced'"

# Только память
adb shell "su -c 'sh /data/adb/modules/golfcore_profiles/profile.sh memory stock'"
adb shell "su -c 'sh /data/adb/modules/golfcore_profiles/profile.sh memory balanced'"

# Полный возврат сохранённых значений и отключение автозапуска
adb shell "su -c 'sh /data/adb/modules/golfcore_profiles/profile.sh restore'"

# После restore автозапуск можно включить отдельно
adb shell "su -c 'sh /data/adb/modules/golfcore_profiles/profile.sh autostart on'"
```

При вызове из обычного терминала на телефоне сначала выполните `su`,
затем нужную команду `sh /data/adb/modules/golfcore_profiles/profile.sh ...`.
Внешние оболочки могут по-разному передавать аргументы `adb shell`; если
команда не передалась, используйте интерактивный `adb shell`, затем `su`.

Отключение модуля в Magisk прекращает применение после следующей перезагрузки.
Для немедленного возврата без перезагрузки используется `restore`.
Удаление через Magisk вызывает uninstall.sh с попыткой восстановления.

## Как работают сохранение и откат

- Перед первым применением в каждой загрузке сохраняется исходный снимок
  в приватном `state/baseline`, связанный с boot_id.
- Старый снимок никогда не воспроизводится в новой загрузке. После её
  завершения service.sh ждёт ещё 30 секунд и применяет выбор однократно.
- Проверяются модель, имя ядра и все числовые значения. Неизвестные профили
  и повреждённый снимок отклоняются.
- Изменение выполняется транзакцией. При ошибке записи или проверки чтением
  уже изменённые значения откатываются. Сохранённый журнал позволяет
  восстановиться после прерванного процесса при следующей операции.
- Для транзакционного отката восстанавливаются только значения, которые
  всё ещё совпадают с записью этого процесса. Внешние изменения не затираются.
  Явная команда restore возвращает все шесть сохранённых значений.
- Постоянного опроса и повторной принудительной записи нет. Если другой
  модуль/Power HAL изменит значения, status покажет расхождение CURRENT/SELECTED.

Для управления логикой Magisk использованы
[официальные инструкции](https://topjohnwu.github.io/Magisk/guides.html).
Описание стандартных VM-параметров:
[документация Linux](https://docs.kernel.org/admin-guide/sysctl/vm.html).
Oplus direct_swappiness проверен по исходникам именно используемого ядра,
а не перенесён из документации новой версии Linux.

## Проверки

`python3 tests/test_profiles.py` — 13 тестов, включая все 36 переходов
между шестью сочетаниями CPU/памяти, точное восстановление, отказ записи
посреди транзакции, устаревшую блокировку, прерывание операции, новую загрузку
и изменение параметра внешним процессом.

На телефоне отдельно проверены все шесть сочетаний, удержание значений
после применения и точное восстановление исходных шести параметров после
каждого режима. Пользователь подтвердил плавную работу Balanced без новых
замеченных проблем при обычном пролистывании и переключении приложений.
Сравнительный тест автономности, FPS и количества перезапусков приложений
ещё не выполнен. Реальная перезагрузка с модулем в этот тест не включена.

При публикации включаются исходники и обезличенный результат проверки.
Индивидуальный state, boot_id и необработанные журналы устройства в Git не добавляются.

Обновление v0.1.1 расширяет проверку имени для GolfCore v0.3. Существующие
профили и значения не меняются. Новое имя проверено на хосте; загрузка самого
ядра v0.3 на телефоне на момент подготовки модуля ещё не проверена.
